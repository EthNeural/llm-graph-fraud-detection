1The big picture

The problem. Fraud detection on graphs. Each user is a node, each connection is an edge, and every user has text (a bio, tweets). Classic graph neural networks (GNNs) mostly ignore that text. Large language models (LLMs) read text well but don't see the graph. The question is how to combine them.

The topic brief names three roles an LLM can play:

  1. Encoder. The LLM turns each user's text into a vector, and a classifier or GNN uses that vector. This is step 3, plus step 4 for the GNN part.
  2. Reasoner. The LLM reads a prompt describing the user and their neighbours and answers Yes or No. This is step 5.
  3. Augmenter. The LLM adds knowledge to a GNN. We touch this with the neighbour summaries in step 5.

The supervisor's twist: evaluate under heterophily. Fraudsters camouflage themselves by connecting to normal users, so "your neighbours look like you" is often false. That breaks the main assumption of GCN-style models.

Remember

Two weak signals: text, and a graph that is barely better than random. The research question is whether LLM + graph gets more out of them than either one alone.

2Graph basics

  • Node = a user. Edge = a connection between two users.
  • edge_index is stored as shape (2, E): row 0 holds the source nodes and row 1 the destinations. That's the PyTorch Geometric convention. The raw file was (E, 2), so step 1 transposes it.
  • Undirected means every edge is stored both ways (a→b and b→a). Instagram has 144,010 rows, so 72,005 real friendships. We checked that no reverse edge was missing.
  • Degree = number of neighbours: np.bincount(edge_index[0]). Instagram's median degree is 12.
  • Isolated node = degree 0. The graph can't help these users, so a GNN only sees their own text. Instagram has 1,838 of them.
  • Induced subgraph: keep a set of nodes, plus only the edges where both ends were kept. Setting B uses this.
Remember

We always report isolated and connected test nodes separately, because the graph can only change predictions for connected ones.

3Homophily and heterophily

Homophily: connected nodes tend to share a label. Heterophily: they don't. Step 1 measures this four ways, because one number can mislead you.

Edge homophily

The share of edges whose two ends have the same label.

h_edge = mean( y[src] == y[dst] )

Instagram: 0.586. That sounds moderately homophilous, but it isn't. If 64% of users are class 0, random edges already land on same-label pairs a lot.

Class homophily hk

Of all edges leaving a class-k node, the share that land on another class-k node.

Instagram: h0 = 0.686 and h1 = 0.392. Class 1 is 36.3% of all nodes, so a class-1 user's neighbours are class 1 only slightly more often than chance. The graph knows almost nothing about class 1.

Class-insensitive homophily (Lim et al., 2021)

This one subtracts the chance level pk (the class's share of all nodes), so it only counts homophily above random. 0 means no better than random; 1 means perfect.

h = 1/(C−1) · Σ_k max(0, h_k − p_k) Instagram: class 0: 0.686 − 0.637 = 0.049 class 1: 0.392 − 0.363 = 0.029 h = (0.049 + 0.029) / 1 = 0.078

0.078 is close to random. This is the honest number.

Node homophily

For each node, the share of its own neighbours with the same label. It gives a distribution per class instead of one number. Instagram class 1 has mean 0.389, and 15.5% of class-1 users have no same-class neighbour at all. Those users are fully camouflaged.

Remember

Edge homophily is inflated by class imbalance. Always look at hk against pk, or at class-insensitive homophily. In Setting B, edge homophily jumps to 0.861, yet h1 = 0.109 against p1 = 0.091: even more heterophilous for the fraud class.

4The two datasets

Instagram (text-attributed graph)

  • 11,339 users, 72,005 undirected edges, text = bio only. Median bio length is 119 characters, and 99 bios are empty.
  • Class 0 = 7,224 (63.7%), class 1 = 4,115 (36.3%).
  • Class 1 is inferred to mean business, brand or media accounts. Its most telling words are we, official, products, magazine, news, click. There is no label file that says this; the dataset doesn't name its classes.
  • Splits: our own stratified 60/20/20 (6,803 / 2,268 / 2,268).
  • We dropped Elliptic, the team's original dataset, for this rebuild.

TwiBot-20 (second dataset)

  • 11,826 labelled users, 6,589 of them bots (55.7%). Bots are the majority here.
  • Text = bio + about 20 tweets, capped at 2,000 characters. Edges are follow links between labelled users: 16,349 of them.
  • The official split is used (8,278 / 2,365 / 1,183), so results are comparable with the literature.
  • Bot hk = 0.516, below the bot share of 0.557. That's heterophilous: bots connect to humans more than chance would predict.

The metadata shortcut

TwiBot-20 also has profile numbers (verified, follower counts and so on). A logistic regression on "verified" alone scores macro-F1 0.803, because only 1 of 6,589 bots is verified. That beats every text model and says nothing about how bots write or connect. So we use text + graph only, no metadata, and report the shortcut as a reference line (report Section 4.6).

Remember

A dataset can contain a "leak" that solves the task without the signal you're studying. Excluding it on purpose, and saying so, is a strength of the method.

5Setting A and Setting B

From the FLAG paper we took exactly two ideas: (1) treat the commercial class as the fraud-like minority, and (2) its 1:10 subsampling. Nothing else.

6Fair evaluation (common.py)

Every model uses the same splits, the same evaluate() and the same threshold rule. Otherwise a comparison table means nothing.

  • Train / validation / test. Train fits the model. Validation picks settings: C, the epoch, the threshold. Test is touched once, at the end.
  • Stratified split keeps the class-1 share the same in every part (0.363 each on Instagram). It uses train_test_split twice, with stratify=y.
  • Splits made once, saved to splits.npz, and reused by every step.
  • No leakage. Fit TF-IDF and scalers on train only. Standardise embeddings with train mean and standard deviation. If test data shapes the model, the test score is inflated.
  • Class weights (class_weight="balanced", inverse frequency) make mistakes on the rare class cost more.
  • Threshold tuning. Model scores aren't calibrated, and 0.5 is a poor cut-off when class 1 is rare. best_threshold() tries 99 quantiles of the validation scores, keeps the one with the best validation macro-F1, then applies it unchanged to test.
  • Seeds. GNNs are trained with 3 seeds; we report the mean ± standard deviation.
  • Early stopping. Keep the epoch with the best validation macro-F1. Stop after 50 epochs with no improvement (patience).
Remember

Validation chooses, test reports. Anything tuned on test is cheating, even by accident.

7Metrics

Accuracy
Share of correct predictions. A bad main metric here. "Always predict 0" gets 63.7% on Instagram A and catches zero fraud.
F1 (class 1)
Harmonic mean of precision and recall on the minority class. It measures how well we catch class 1 without false alarms.
Macro-F1 (main metric)
F1 for each class, averaged equally. Majority-class guessing scores only 0.389, so it can't be gamed that way.
AUROC
The probability that a random class-1 user gets a higher score than a random class-0 user. 0.5 = random. It doesn't depend on the threshold.
PR-AUC
Area under the precision–recall curve for class 1. A random model scores the class-1 share (0.36 in A, about 0.09 in B), so it's much harsher than AUROC when fraud is rare.
conn / iso
Macro-F1 on connected and on isolated test nodes separately. This shows whether the graph helped where it could.

8Step 2: baselines

The bar every fancy model must clear. If an LLM or GNN can't beat these, it isn't earning its cost.

  1. Majority class: predict the most common training label for everyone. This is the floor.
  2. TF-IDF + logistic regression: text only, no graph, no LLM. TF-IDF scores words that are frequent in this bio but rare overall. Settings: 1–2 word phrases, at most 20,000 features, min_df=2, sublinear_tf.

On Instagram A, TF-IDF reaches macro-F1 about 0.58 with AUROC only 0.59. Text alone is weak, and step 1 showed the graph is barely better than random. On TwiBot-20 A, TF-IDF does much better (0.70), because tweets carry more signal than short bios.

Remember

"balanced" class weights can lower accuracy while raising macro-F1 and class-1 F1. A fraud team prefers catching fraud over a flattering accuracy.

9Step 3: LLM as encoder

Turn each user's text into a vector (an embedding), then train logistic regression on it. The embeddings are cached in emb_<name>.npy and become the node features for step 4.

Two kinds of encoder

  • Sentence encoders (MiniLM, multilingual-E5, English E5-base, Qwen3-Embedding) are trained to output one vector per text directly. Both E5 models expect a "query: " prefix.
  • Decoder LLMs and plain pre-trained models (Qwen2.5-1.5B, Twitter-RoBERTa) output one vector per token. We mean-pool them: average the token vectors, using the attention mask so padding is ignored.

Gotchas we hit

  • Empty text gives NaN. Qwen adds no start token, so an empty bio becomes zero tokens and the mean pooling divides 0 by 0. Fix: a placeholder text "[empty bio]".
  • Outlier dimensions. Decoder hidden states have a few huge dimensions, so StandardScaler goes before logistic regression.
  • Regularisation C is tuned on validation from {0.001, 0.01, 0.1, 1}.
  • Long TwiBot-20 text (about 570 tokens) won't fit an encoder's 128-token window. So we encode each piece (the bio, each tweet) separately, L2-normalise each piece vector, and average them per user. A user with no text gets a zero vector plus 0/1 flags for "no bio" and "no tweets". Nobody is dropped.

10Step 4: GNNs, the heterophily test

Message passing: each layer updates a node from its own features and its neighbours'. Two layers let information travel two hops.

GCN : h_v = W · mean over {v and its neighbours} of x_u (self and neighbours MIXED) SAGE: h_v = W1 · x_v + W2 · mean over neighbours of x_u (self and neighbours SEPARATE)

Why it matters under heterophily. GCN averages a class-1 user together with mostly class-0 neighbours, which blurs exactly the users we want to find. SAGE keeps a separate weight for "me", so the model can learn to trust its own text more than its neighbours'. Prediction: GCN ≤ text-only, and SAGE holds up better.

Two controls make it a clean experiment

  • MLP: the same 2-layer network with the edges ignored (NoGraph). This is text only.
  • Graph-only: GCN or SAGE on structure features alone (log degree and mean neighbour degree). No text.

So "text only vs hybrid" differs only in whether the graph is used.

Training recipe (same for all): 2 layers, hidden size 128, dropout 0.5, Adam with lr 0.01 and weight decay 5e-4, class-weighted cross-entropy, up to 300 epochs with patience 50, 3 seeds.

Remember

On TwiBot-20 A, GCN lost 0.04–0.06 macro-F1 against MLP for every encoder. SAGE stayed close to MLP. That's the heterophily prediction, confirmed.

11Step 5: LLM as reasoner

The LLM (Qwen2.5-1.5B-Instruct) answers a Yes/No question zero-shot, meaning it gets no training on our labels. The question is "Is this a business/brand account?" for Instagram and "Is this a bot?" for TwiBot-20.

Three prompt variants, to isolate what helps

VariantThe prompt containsTests
targetTarget's text onlyNo graph
rawTarget + 8 neighbours' full textsFine + fine
dgpTarget + 8 neighbours' summariesFine + coarse (Dual Granularity Prompting)
  • Summaries: each neighbour's text is condensed to at most 25 words (a 32-token budget) with a task-agnostic prompt that never mentions the label. They're cached in summaries.json, which is why the restart after the shutdown didn't redo them.
  • Which 8 neighbours? The ones most similar to the target by cosine similarity on multilingual-E5 embeddings. On a heterophilous graph, this filters out the most different (likely other-class) neighbours.
  • Scoring: one forward pass. Take the logits for the tokens "Yes" and "No" at the last position, apply a softmax, and use P(Yes) as the score. The threshold is tuned on a validation sample.
  • Sampling: LLMs are slow, so the test set is a stratified sample. On that same sample we re-score Qwen + LR and Qwen + GCN for a fair comparison.
Remember

On Instagram A, the zero-shot reasoner (0.553) lost to the trained Qwen + LR (0.607) on the same sample, and DGP (0.537) didn't beat target-only. Reading neighbours didn't help, because the neighbours are mostly the other class.

The findings, in plain words

  1. A better encoder is the biggest win. On TwiBot-20 A, going from TF-IDF (0.70) to Qwen2.5 + MLP (0.766) beats anything the graph adds.
  2. The graph adds little, and its gain shrinks as the encoder improves. On Instagram A, GCN lifts MiniLM from 0.588 to 0.607 but does nothing for Qwen2.5 (0.608 to 0.609).
  3. GCN hurts under heterophily on TwiBot-20: below MLP for every encoder in A. SAGE, which keeps "self" separate, loses much less. In B, Qwen2.5 + SAGE edges past MLP (0.624 vs 0.613), but the gap is within about one standard deviation (±0.012–0.015).
  4. The graph alone is weak: 0.577 in A, and near the floor in B (0.497).
  5. The zero-shot LLM reasoner loses to trained models, and adding neighbours (raw, dgp) doesn't reliably help. That's consistent with neighbours being mostly the other class.
  6. Size isn't everything. The tweet-trained 125M model beats the 0.6B LLM embedder.

13Running it on a laptop

  • Cache the slow parts: embeddings (.npy) and summaries (.json, saved every 20 batches). Re-runs then redo only the cheap parts, and a crash loses little.
  • Half precision (fp16) on the Mac GPU (mps) is about 2× faster and uses half the memory.
  • Sort texts by length before batching, so batches carry little padding. Then restore the original order.
  • Swap is the enemy. With 16 GB of RAM, Chrome and VS Code pushed swap to 10 GB, and batches went from 8 seconds to 5–10 minutes. Quitting apps fixed it.
  • caffeinate stops the Mac from choosing to sleep. It can't stop a flat battery, or a sudo shutdown -h +50 timer, which is what ended the 2 November run.
  • Environment switches: DATASET=twibot20, SETTING=B, SKIP_ENCODERS=qwen. One codebase, every experiment.

14Glossary

Embedding
A list of numbers that represents a text. Similar texts get nearby vectors.
Cosine similarity
The angle-based similarity of two vectors. For unit vectors it's just the dot product.
Mean pooling
Averaging the token vectors into one text vector, ignoring padding.
L2-normalise
Scale a vector to length 1, so its length can't dominate an average.
Logits
The model's raw scores before softmax. We compare the logits for "Yes" and "No".
Zero-shot
Asking a model to do a task it wasn't trained on, with no examples.
Regularisation (C)
Controls how hard logistic regression is pushed towards simple weights. Smaller C means stronger regularisation.
Weight decay
The same idea for neural networks: a penalty on large weights.
Dropout
Randomly zeroes features during training so the network can't rely on any single one.
Early stopping / patience
Keep the best-validation epoch, and stop after N epochs without improvement.
Stratified sampling
Sampling that keeps the class proportions the same.
Data leakage
Test information reaching training or tuning, which inflates the scores.
Camouflage
Fraudsters connecting to normal users so they look normal to a graph model.
DGP
Dual Granularity Prompting: the target in full detail, neighbours as short summaries.

15Test yourself

Say the answer out loud, in your own words, before you open it.

Why is 0.586 edge homophily misleading on Instagram?

Class 0 is 64% of users, so even random edges often join two class-0 users. After subtracting chance, class-insensitive homophily is only 0.078, which is close to random.

Class 1 is 36.3% of nodes and h1 = 0.392. What does that tell you?

A class-1 user's neighbours are class 1 barely more often than random (0.392 vs 0.363). The graph carries almost no information about class 1.

Why does Setting B show edge homophily 0.861 when it is more heterophilous?

91% of nodes are class 0, so nearly all edges are 0–0. That inflates the edge score. For the fraud class, h1 = 0.109 against a chance level of 0.091, which is almost no signal.

Why is accuracy a bad main metric here?

"Always predict normal" scores 63.7% (A) or about 91% (B) while catching zero fraud. Macro-F1 weights both classes equally, so it can't be fooled that way.

Why must the TF-IDF vectorizer never be fitted on test text?

Its vocabulary and IDF weights would then contain test information. That's data leakage, and it inflates the test score.

Why pick the threshold on validation instead of using 0.5?

Class weights and LLM logits shift the scores, so they aren't calibrated probabilities. When class 1 is rare, 0.5 is badly placed. Picking it on validation (not test) keeps the test score honest.

What's the difference between GCN and SAGE, and why does it matter here?

GCN mixes a node with its neighbours in one average. SAGE has a separate weight for the node itself and one for its neighbours. Under heterophily, the neighbours are mostly the other class, so GCN blurs the fraud users while SAGE can learn to trust their own text.

Why include the MLP and graph-only controls?

MLP is the identical network without edges, so "MLP vs GCN" isolates the effect of the graph. Graph-only shows how much the structure knows without any text (0.577 on TwiBot-20 A).

What will a GNN predict for an isolated node?

With no neighbours, it can only use the node's own features, so it behaves like the MLP. That's why the iso column is reported separately.

Why did we mean-pool Qwen2.5 but not MiniLM?

MiniLM is a sentence encoder that outputs one vector per text. Qwen2.5 is a decoder LLM that outputs one vector per token, so we average them, using the attention mask to skip padding.

What caused the NaN embeddings, and how did we fix it?

An empty bio became zero tokens (Qwen adds no start token), so mean pooling divided 0 by 0. We replaced empty text with a placeholder, "[empty bio]".

How does TwiBot-20 text fit into a 128-token encoder?

Encode each piece (the bio, each tweet) separately, L2-normalise each vector, then average per user. Users with no text get a zero vector plus "no bio" / "no tweets" flags.

Why exclude TwiBot-20 metadata?

"Verified" alone scores macro-F1 0.803, because only 1 of 6,589 bots is verified. It's a shortcut that says nothing about text or graph, so it would hide the effect we're studying. It's reported only as a reference line.

In DGP, why are the summaries task-agnostic?

If the summary prompt mentioned bots or businesses, the LLM's summary would already contain a guess at the label. Keeping it neutral means the reasoner, not the summariser, makes the decision.

Why choose the 8 most similar neighbours?

On a heterophilous graph, many neighbours are the other class. Picking the ones most similar by multilingual-E5 cosine similarity filters out the most misleading ones and keeps the prompt short.

Why compare the LLM reasoner on the "same sample"?

The LLM is scored on a stratified sample of the test set, not all of it. Re-scoring Qwen + LR and Qwen + GCN on exactly those users makes the comparison fair.

What's the single main finding?

Better text encoders give the biggest gains. The heterophilous graph adds little, and the gain shrinks as the encoder improves. GCN actively hurts, SAGE is safer, and a zero-shot LLM reasoner doesn't beat trained models.
